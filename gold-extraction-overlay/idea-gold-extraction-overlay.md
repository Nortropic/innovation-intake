# Idea brief: Nortropic Gold Extraction overlay

## 1. Summary
An owner-adopted standing mode for external finds (repos, screenshots, papers,
releases): extract *guldet* (the whole/architecture), *guldkornen*
(primitives/techniques), the method behind it, and the anti-gold (what Nortropic must
avoid), mapped to a Nortropic delta and a disposition
(KEEP/ADAPT/ADD/SIMPLIFY/MERGE/REJECT/DEFER/EXPERIMENT/FRONTIER_WATCH). The framing
decision: this is explicitly an overlay ON TOP OF the preserved Deep Brainstorm
definition, never a replacement (← msg 18). Operationally it ran as uncurated GitHub
dumps in batches of ~10 with compressing cross-batch synthesis.

## 2. Context you need
Johnny regularly finds external builds he wants mined for Nortropic value (← msg 16).
A memory already defines what "brainstorma" means (deep, iterative, critical
exploration); the owner required that definition kept intact when the Gold Extraction
lens was added (← msg 18, 20). The mode was then used through nine repo batches plus
closing material in the same conversation (msgs 27–62, assistant analyses). Whether
this package is a CONTINUATION of `arbetsmetoder-innovation` or DISTINCT is pending
owner review — see §9.

This brief is the primary intake artifact for execution. Deeper design logic lives in
the linked design rationale; the full chat is raw evidence — read targeted message
ranges only if the rationale is insufficient. Current canonical repository authority
beats all intake artifacts; within the intake package this brief wins over rationale
and transcript. Once an owner-approved plan is bound (see the frontmatter), it carries
execution order above this brief and below current repository authority.
Invariants this must not violate: Nortropic's trust layer — constitution & rulebook
(`nortropic-system/docs/07-konstitution.md`, `03-regelverk.md`): trust contracts,
frozen gates, §-rules. Pointer only — read them there; never copied here.

## 3. Destination (goal, not implementation plan)
- A durable, documented working protocol: when Johnny sends external material with
  "brainstorma", the full Deep Brainstorm process runs with the Gold Extraction layers
  on top, ending in dispositions and Nortropic placement.
- Batch operation for bulk material: uncurated dumps of ~10, deep per-item extraction,
  cross-item combination hunting, periodic meta-syntheses that compress ("after 100
  repos we want 12 principles, not 650 ideas").
- Provenance preserved per conclusion (concept → origin → derived-in → status) so
  later extraction-for-implementation can return to originals.
- Choose form (memory text, skill, protocol doc) yourself, within §6.

## 4. Decisions already made (do not relitigate silently)
D1. Recurring mode adopted: "utvinna guldet dvs en helhet eller guldkornen dvs delar
eller detaljer, tillvägagångssätt ur de till Nortropic" — because Johnny keeps finding
such material and wants systematic extraction, not ad hoc opinions (← msg 16;
four-layer analysis 17).
D2. The old brainstorm definition (the memory) is kept — Gold Extraction must not
replace it — because the deep process (framing, research, hypotheses, adversarial
critique, second-order effects, synthesis) is the foundation the lens sits on
(← msg 18; 19).
D3. The merged definition was requested and fixed explicitly ("Kan du ge mig
definitionen nu") — because the combined contract (12-step process + Gold Extraction
block) is the reference for every future "brainstorma" (← msg 20; definition 21).
D4. Batch method adopted: "Jag skickar de 10 och 10"; later everything in Improvements
is extracted for implementation — because batches give rhythm (batch → research →
extraction → cross-synthesis → next batch) and mining stays separate from
implementation (← msg 24; method 25).
D5. Mining-phase close was an explicit owner act ("Avslutningsvis, brainstorma
dessa") — because the final batch stress-tests the accumulated conclusions rather than
adding features (← msg 61; 62).

R1. Pre-curating or justifying each repo before sending — because the analyst should
discover value the sender didn't see; the owner followed the uncurated-dump protocol
with bare URL lists (← msg 26–27; requested 25).

## 5. Acceptance criteria (v1)
AC1. WHEN Johnny sends external material and says "brainstorma", THE analysis SHALL
apply the merged definition: the full Deep Brainstorm process plus the Gold Extraction
layers (guldet, guldkornen, metoden, anti-guld, Nortropic delta, disposition), and
SHALL separate evidence from judgment (← msg 16, 20; 17, 21).
AC2. WHEN bulk material arrives, IT SHALL be processed in uncurated batches (~10) with
per-item extraction, cross-item combination hunting, and periodic meta-syntheses that
compress and merge rather than grow the backlog (← msg 24, 26; 25).
AC3. WHEN a conclusion is derived from an external source, ITS provenance SHALL be
recorded (concept, origin, derived-in, reinforced-by, status) so later
extraction-for-implementation can reach the original material (← msg 24; 25).
AC4. WHEN a source's authority cannot be verified (e.g. an unverifiable claim behind a
screenshot), THE idea SHALL be kept while the authority gloss is discarded until
provenance exists (← msg 22; practice 23).

## 6. Constraints & implementation notes (right altitude — suggestions, not orders)
Invariants pointer: Nortropic's trust layer — constitution & rulebook
(`nortropic-system/docs/07-konstitution.md`, `03-regelverk.md`); pointer only.
Suggestions from the source: classify finds as FOUNDATIONAL / CAPABILITY / TACTICAL so
a neat trick never outweighs an architecture shift; a good outcome may be "don't use
this product, but two ideas are valuable" or "we can delete something we planned";
extraction stays separate from implementation until the post-Bootstrap phase; the
disposition vocabulary should match the one used by the recompile work.

## 8. Verification (how we know it works)
From the record alone: given a fresh external find and the trigger word, the produced
analysis demonstrably contains all Gold Extraction layers, a disposition per finding,
separated evidence/judgment, and provenance lines that resolve to the original
sources; a batch run additionally shows a cross-batch synthesis whose idea count
shrinks relative to the raw finding count.
