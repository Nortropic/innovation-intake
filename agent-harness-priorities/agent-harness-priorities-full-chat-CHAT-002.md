Under körningen dokumenteras kommandon, resultat och tolkningar; efteråt fångas även dead ends, valda alternativ, varför de valdes och vad nästa run bör göra annorlunda. Ett `*.index.md` gör tidigare runs sökbara. OpenAI beskriver samtidigt automatic approval review som något som arbetar **utan att ändra befintliga permission boundaries**. citeturn279624search1 **Implikation:** det här är mycket relevant för Nortropics context-/handoff-problem. Evidence-rapporten bör inte växa till en roman, men varje slice kan producera ett tunt **run index** bundet till task + candidate SHA som pekar på plan, commands/results, reviewer findings och viktiga dead ends/decisions. Det blir återanvändbar operational memory utan att bli scheduler, doneness-store eller ny authority. Lärdomar från gamla runs får förbättra nästa plan men aldrig automatiskt modifiera frozen gates.

- **OpenAI har nu ett officiellt Claude→Codex interoperabilitetsmönster.** Dokumentationen “Submit your Claude Code plugin to OpenAI” säger uttryckligen att Claude-skills kan behålla `SKILL.md`, att Claude-specifika instruktioner bör göras provider-neutrala (“the model”), och att återanvändbara Claude `commands` och `agents` bör konverteras till skills. Hooks ska adapteras per runtime och får inte vara nödvändiga för den gemensamma kärnworkflown. OpenAI kräver dessutom att importerade skills testas i **clean environment** så att de inte implicit beror på lokala filer, paket eller credentials. citeturn279624search0 **Implikation:** detta är den starkaste officiella valideringen hittills av en verklig **Claude↔Codex shared operating layer**. Nortropics `builder/test-author/reviewer` bör fortsätta vara provider-neutrala processkontrakt; Claude- och Codex-specifika saker hör hemma i tunna runtime adapters. Lägg senare till portability-evals: samma skill körs i ren Codex-miljö och ren Claude-miljö mot samma synthetic task, och skillens kärnsemantik ska bestå även om hook-/tool-implementationen skiljer sig.

Det jag **inte** hittar är också viktigt: det finns fortfarande inget nytt officiellt mönster från OpenAI eller Anthropic som gör **symmetrisk Claude↔Codex-debate, majoritetsröstning eller auto-merge** till trust authority. Tvärtom ökar autonomin i execution (`/loop`, background agents, automated approval review) samtidigt som permission-/reviewgränserna blir mer explicita. För Nortropic bör alltså **autonomous execution och autonomous promotion förbli två olika problem**.

Min prioriterade “delta” för nästa operating-model-revision skulle därför vara:

```text
2. CANDIDATE_SHA + ENVIRONMENT_PROFILE_ID + ACTUAL_MODEL

```

Det är **guldet den här veckan**: inte fler agenter, utan ett allt tydligare industry pattern för att göra ett agentträd **bounded, provenance-aware, capability-minimal och återupptagningsbart utan att göra modellens egen utsaga till sanning**. memcite
